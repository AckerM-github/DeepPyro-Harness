# Release 0.3.0（native-only）

> **状态：v0.3.0 已打 tag；Web UI 为 tag 之后的未发布增补（2026-11-20 起为 React SPA）。** 本文件
> 对应 0.3.0 native-only 硬切，并记录随后落在 main 上的 Web UI（React SPA 版本，下一版本发布时
> 一并打包）。0.2.0 的发布说明与已知问题表已标记为历史文档；本文件是 0.3.0 范围的唯一总表。

## 1. 版本主题

0.3.0 只做一件事：**把“过渡期”删干净**。

- 只有一种会话格式：native schema 1（`~/.dpro/sessions/<id>.jsonl`）。
- 只有一条 agent 路径：native `AgentLoop` + `NativeAgentHost`。
- 只有一种 provider 抽象：`core.llm.LlmProvider`（OpenAI 兼容 + Anthropic 原生）。
- 三个入口共享同一个运行时：TUI、headless、仅回环的 Web UI。
- 旧 v4 的会话、wire、projection、session-query、迁移工具和回退开关全部删除，不保留 shim。

## 2. 破坏性变更

### 2.1 v4 会话/运行时删除

- 删除 `core.wire`、v4 session reader/writer/derive/events/fork/metadata/store/session、v4 agent loop/session、
  `projection`、`session_query`、旧 compaction/goal/llm 分支与对应测试。
- 删除 `dpyro migrate` 与 `session/migrate_cli.py`、`session/migrate_service.py`、`migrate.py`。
- 删除 `zstandard` 运行时依赖；会话不再有 `.jsonl`/`.zstd` 双格式。
- **旧 `session.v4.jsonl` 不再可读。** 升级前请备份 `~/.dpro/sessions`；0.3.0 不提供迁移命令，
  也不做 v4 兼容读取。

### 2.2 回退开关与旧入口删除

- 删除 `--legacy-v4`、`--native-loop`、`DEEPPYRO_NATIVE_LOOP`、`DEEPPYRO_TUI_NATIVE`。
- 删除 `dpyro migrate` 分发与 `migrate` 子命令。
- 删除 `llm/messages.py`、`llm/anthropic.py`、`llm/openai_compat.py` 等 v4 provider/message 层；
  native provider 是唯一实现。
- 删除 core bundle 中的 `session-migrate`、`llm-retry`、`hook-journal`、`session-query`、`projections` 行。

### 2.3 TUI 与启动页

- TUI 的会话、turn、tool、team/subagent、goal、hooks、compaction、PTC 全部走 native。
- 启动页改为 **F1 = Web，F2 / Enter = 终端**；任意键不再继续。
- F1 退出 TUI 后在当前进程启动 Web 宿主并打印带 token 的 URL；F2 进入终端；`--resume` 在两种入口都保留。
- TUI 不再读取旧 v4 会话；`/sessions`、`/resume`、`/fork` 只操作 native 会话。

### 2.4 Web UI（React SPA 生产形态，tag 后增补）

- `WebHostPlugin`（`provide="web"`）是 native 运行时的宿主外壳，不是第二个 agent；
  `python -m deeppyro.web --port 0 --cwd PATH` 可独立运行，也可从 TUI splash 按 `F1` 进入。
- 浏览器端是 **React 19 + TypeScript + Vite 8** 单页应用，源码在 `web/`，构建产物
  `src/deeppyro/web/ui/static/`（`index.html` + 哈希 `assets/`）提交进仓库并随 wheel 发布；
- 服务器只提供同源静态文件、JSON API 与 SSE，无 CDN、无外部字体、无 WebSocket。
- 三栏原创界面（Discord 密度，自有品牌/图标/字体）：会话侧栏（品牌位于顶部）、
  聊天舞台、session inspector；<768px 侧栏收进抽屉，Inspector 在 <1280px 收起。
- 真实 native 数据：会话列表/创建/resume/timeline、流式文本与推理、工具卡、usage/context、
  中断；SSE 以 `?after=<seq>` 续订，timeline 暴露 `journal_seq` 防重复回放。前端自管重连
  （800ms 起指数退避、上限 10s，`online` 立即重试）。
- **工具审批**：越界工具调用挂起为审批卡（工具名、摘要、目标、Allow once/Deny），
  工具卡保持 PENDING，决策后继续或拒绝；默认 300 秒超时，turn 结束会清理。
- **命令 UI 化**：命令面板与 composer slash 共用 `POST /api/ui/commands`；25 个 core command
  分别落到真实执行、导航、只读或明确拒绝，未接宿主的能力不假装成功。
- **设置 UI 化**：Provider/model/API key/温度/token 上限/权限/命令/插件设置；写盘前
  `Config.model_validate`，原子替换并生成 `.bak`/编号备份；agent/provider/permission 保存后通过
  live apply 从下一 turn 生效（streaming 时 defer），web port 等配置仍需重启。
- 安全：只监听 `127.0.0.1`/`localhost`；每进程随机 bearer token，首次页面换成
  `dpyro_web_<port>` 的 HttpOnly/SameSite=Strict cookie 并 303 去 token；Host/Origin/Sec-Fetch-Site
  校验；body/header 上限；单 attached session；无 TLS。CSP 为 `script-src 'self'`、
  `style-src 'self'`，无 `unsafe-inline`/`unsafe-eval`；`/assets/*` immutable 缓存，shell 与
  `/brand` no-store。

### 2.5 provider port

- 新增 `core/llm.py`：`StopReason`/`Usage`/`ToolSpec`/`ModelRequest`/流事件/`LlmProvider`/`ModelResponse`/`NativeToolCall`。
- `agent/model_call.py` 是唯一模型调用入口；重试、usage、trace 与 retry_count 进入 `ModelCallRecord`。
- native OpenAI 兼容 provider 与 native Anthropic provider（Messages API + SSE）为仅有的两个传输实现；
  不支持 native 传输的 provider 直接报错，不静默降级。

### 2.6 native 能力收口

- **team/subagent**：子会话用 `origin="subagent"`、`parent_id`、`delegation_depth+1` 创建；
  facts 写 `plugin.team.*` / `plugin.subagent.*`，usage 只经 `UsageSink`，不写会话正文。
- **goal**：`NativeRoundDriver` 按 fold 的 `goal.changed.rounds_started` 推进；pause/block/complete 中断。
- **compaction**：每次压缩恰好一条 `compaction.done`（`compaction_id`/`covers`/`message`）；
  refs sidecar 支持可寻址历史；工具安全切点。
- **PTC**：native adapter 走同一 AgentLoop；PTC preset 在 native host 可用。
- **task/handoff**：native 核心事件 `task.state`/`task.handoff`/`task.handoff.result`。
- **bundle 平台**：可选 HMAC-SHA256 签名、bundle group 子行 patch、TUI slot 显式 REPLACE/OVERRIDE。

### 2.7 配置与插件

- 配置继续严格 snake_case；camelCase alias 与 `strict_config` 开关仍被拒绝。
- **旧配置自动升级**：CLI 启动时（`--version` 之后、布局迁移之前）调用
  `config.migrate_legacy_config()`，把 0.2.x 的 camelCase 键、`[agent].permissionPreset`、
  `[agent].approvalPolicy` 改写为 0.3 形状；保留注释与顺序，写盘前用严格模型校验，失败不写盘，
  并生成 `.bak`/`.bak.N` 备份。库调用 `load_config` 仍不隐式改写。
- 插件 API v3 硬切不变；core bundle 现有 **41 个插件行**（另有 `[bundle]` 元数据）和 `version = "0.3.0"`。
- host 级服务解析只接受契约类。

## 3. 升级步骤

1. 备份 `~/.dpro`，尤其是 `sessions/` 和 `config.toml`。0.3.0 不会自动改写旧会话，也不会读取它们。
2. 升级到 0.3.0 后首次启动会使用 native schema 1 写新会话；旧 v4 文件留在原目录但被忽略。
3. 首次运行 CLI 时旧 `config.toml` 会被自动迁移到 0.3 schema（生成 `.bak`/`.bak.N` 备份，
   注释和键顺序保留）。如果校验失败，进程会报错并且不改写配置；此时按
   `docs/guides/config-migration.md` 手工迁移。
4. 去掉脚本/CI 中的 `--legacy-v4`、`--native-loop`、`DEEPPYRO_NATIVE_LOOP`、`DEEPPYRO_TUI_NATIVE`
   与 `dpyro migrate`；这些参数现在直接报错。
5. Web UI 与 TUI/headless 共用 `~/.dpro` 的会话与配置；首次打开 URL 后 token 会换成 cookie，
   重启宿主后旧 URL 失效，从新 banner 取地址即可。
6. 插件按 v3 检查；确认没有 import `deeppyro.core.wire`、`deeppyro.session.store`、
   `deeppyro.projections`、`deeppyro.session_query`。API v1 插件（例如旧的 `dpyro-im`）不会阻止启动，
   但会以非致命警告跳过，需要移植到 `Plugin.setup(self)`。
7. 需要旧对话时，从备份用 0.2.0 读取/人工导出；0.3.0 不再提供格式转换。

## 5. 已知限制

- **会话没有迁移路径**：旧 v4 会话不可读；这是有意的硬切，不是待修 bug。配置仍会由 CLI 自动升级。
- **Web UI 是本地单用户外壳**：无 TLS、无远程绑定、单 attached session；审批只覆盖宿主发起的
  工具调用；SSE journal 只在进程内，重启后靠 timeline 回放；无多会话并行、附件上传、compaction UI。
- **Windows 沙箱是 partial**：受限 token/ACL，不是容器/虚拟机隔离。
- **memory 是 SQLite FTS5**：有 `memory_search`/`memory_add`，无 embedding/vector。
- **合成差分不是录制**：七类形状覆盖不等于真实 provider 录制；录制基线仍是 10 例。
- **插件平台边界**：bundle 签名只证明共享密钥持有者签发过字节；没有 OS 沙箱/进程内隔离；
  group 子行只能改既有子行；TUI slot 默认 append-only，替换需显式 opt-in。
- **usage/trace 默认本地**：OTLP 导出默认关闭；trace 不存正文。
- **去品牌**：`src` 只剩 **26 行 / 4 文件**的功能兼容常量：MCP 子进程环境前缀 `DSH_`、
  skills 的 `.dsh` 目录与 `project-dsh`/`user-dsh` 来源名。注释与 docstring 已统一改为
  “upstream”；`tests`（57 行）和 `docs`（405 行）中的旧名称是测试常量、历史发布说明或
  ADR/archive 记录，不是模型可见文案。
