# Release 0.2.0（发布准备中）

> **状态：未发布。** 本文是 0.2.0 的 release note 草案，随 M5 提交。
> 基线 commit：`35b433f`（M1：native schema 1 + trace 骨架）。
> **发布阻塞项**：M2（native loop）、M3（插件 API v3 + snake_case config）、M4（eval/memory/multi-agent）尚未合流；
> 它们完成并过门禁前，0.2.0 不能发布。当前仓库版本号已改为 0.2.0（`pyproject.toml`、`src/deeppyro/__init__.py`），
> 但运行时仍是 0.1.0 行为，见 §6。

## 1. 版本主题

0.2.0 是 DeepPyro Harness 的第一次破坏性版本，主题是三条主线（ADR D5）：

- **插件化（P）**：一种 mount 形状（`setup(self)`）、typed `inject`、服务类型化、能力清单 `CapabilityManifest`。
- **Python 化（Y）**：会话只使用 native schema 1；消息/事件/循环用 Python 类型表达；不再复刻外部 harness 的 wire 形状。
- **AI 原生（A）**：session log 只记事实，token/时延/重试进本地 trace；为回放、checkpoint、eval、memory、multi-agent 铺路。

一句话：0.2.0 起 DeepPyro 不再是“某个 harness 的 Python port”，而是自己的 native harness。

## 2. 破坏性变更

### 2.1 会话：v4 不再是主路径

- 产品只读写 native **schema 1**：`~/.dpro/sessions/<session-id>.jsonl`，24 个核心 `EventKind`，dotted 小写事件名。
- 旧的 `session.v4.jsonl` / `.zstd` **不读不写**；打开旧会话显式失败（`SessionV4Error`），不会降级或尽力修复。
- 不提供 `dpyro migrate`、不 dual-write、不保留 v4 reader；旧数据导出是仓库之外的一次性脚本，不进产品与 CI。
- 删除的 v4 机制：`surfaceOp`、`sourceEventSeqs`、`ignorable`、62 种斜杠记录类型、interval surface folding；
  消息以稳定 `message.id` 定位（替换用 `message.replaced` / `compaction.done` 表达）。
- 影响：所有依赖旧会话格式的脚本、视图、插件需要重写；旧会话历史不可在 0.2.0 中打开。

### 2.2 配置：camelCase → snake_case

- 0.2.0 目标配置为 snake_case；旧 camelCase 键不再被识别（M3 实现）。
- 范围：`~/.dpro/config.toml`、插件 row 的 `config` 表、仓库内文档示例。
- 预期映射（**以 M3 实现为准**，未定稿项标 `TODO(config)`）：

  | 旧（camelCase） | 新（snake_case） |
  | --- | --- |
  | `agent.maxTokens` / `maxSteps` | `agent.max_tokens` / `max_steps` |
  | `providers.<id>.baseURL` | `providers.<id>.base_url` |
  | `providers.<id>.apiKeyEnv` | `providers.<id>.api_key_env` |
  | `providers.<id>.models[].contextWindow` | `context_window` |
  | `sessionDir` | `session_dir` |
  | `sandbox.additionalWritableRoots` | `sandbox.additional_writable_roots` |
  | `retry.maxRetries` / `initialDelayMs` / `maxDelayMs` / `jitterRatio` | `max_retries` / `initial_delay_ms` / `max_delay_ms` / `jitter_ratio` |
  | `goal.maxGoalRounds` / `blockedAfterConsecutiveRounds` | `max_goal_rounds` / `blocked_after_consecutive_rounds` |

- 旧 `extra="allow"` 的宽松行为收紧，未知键处理见 M3 结论（`TODO(config)`）。

### 2.3 插件 API：v2 → v3 硬切

- `api_version` 从 2 升到 3，无兼容 shim；v1 的 `setup(self, ctx, config)` 被移除。
- 唯一 mount 形状：adapter 以 `(ctx, config)` 构造，fiber 激活调用无参 `setup(self)`，插件读 `self.ctx` / `self.config`。
- typed `inject`：依赖用契约类声明；插件侧不再用字符串 `.service("name")` 查找（门禁：零 string service 调用）。
- 新增 `CapabilityManifest` 能力清单（字段与校验规则在 M3 定稿，见 `docs/plugins/migration-v2-v3.md` §6）。
- 安装通道增加 entry points（细节 TODO(api-v3)）；现有 `plugin.toml` 包与 bundle 目录形态保留。
- bundle `api_version` 随 API 升到 3；显式写 2 的 bundle 需要同步更新。
- 完整迁移步骤与逐项对照：`docs/plugins/migration-v2-v3.md`；插件作者指南：`docs/plugins/README.md`。

### 2.4 旧 DSH 路径归档 / 去品牌

- `docs/spec/INTERFACES.md`、`docs/spec/session.md` 已冻结并标记由 native 契约取代；
  `dsh-event-catalog*` 两篇是外部 harness 逆向目录，随 v4 移除退役。
- 旧 DSH 路径（`~/.dsh`、DSH 事件名、TS/Node fixtures、`tools/gen_fixtures.mjs`）不再作为产品依赖；
  CI 不安装 Node。
- 去品牌门禁：`rg -i dsh src` 接近 0（当前未达标，审计与清理建议见 `docs/release/dsh-audit.md`）。

## 3. 迁移步骤

### 3.1 普通用户

1. 备份 `~/.dpro`（尤其 `sessions/`）；升级后旧会话不会被打开，备份是唯一恢复手段。
2. 需要保留旧会话历史时，用仓库之外的一次性导出脚本转成文本/JSON；0.2.0 不提供导入。
3. 按 §2.2 把 `~/.dpro/config.toml` 改写为 snake_case（保留旧文件备份）。
4. 启动 `dpyro` 验证 provider/model/权限配置；旧会话从空开始新建。
5. 旧 `plugins.toml` / 用户 bundle 按 `docs/plugins/migration-v2-v3.md` 迁移。

### 3.2 插件作者

1. 先把 `setup` 改为无参、`inject`/查找改用契约类（v2 即可运行，见迁移文档 §2）。
2. 配置字段改 snake_case；去掉对 `core.wire`、`session.v4`、`surfaceOp` 的依赖。
3. 等 M3 合流后声明 `api_version = 3`、补 `CapabilityManifest`、按 entry point/包格式重新安装。
4. 用 `boot(cfg, bundle_paths=[...])` + `dpyro plugin doctor` 回归。

### 3.3 集成/运维

1. 升级到 `deeppyro-harness==0.2.0`（发布后），环境变量名不变：`DEEPPYRO_HOME`、`DEEPPYRO_CONFIG`、
   `DEEPPYRO_SESSIONS_DIR`、`DEEPPYRO_TRACES_DIR` 等。
2. 确认 CI 不安装 Node；检查无旧 fixture 依赖、无 skip 用例。
3. 若使用自定义监控：0.2.0 没有遥测上报；本地 trace 只含 hash/计数/时延，不能替代业务日志。
4. 回滚：重新安装 `0.1.x` 并使用升级前备份的 `~/.dpro`；0.2.0 产生的新会话不能降级读取。

## 5. 已知限制（0.2.0 发布时仍存在）

- **M2/M3/M4 合流中**：native loop、API v3、eval/memory/multi-agent 的最终形态以合流后代码为准；本文相关条目可能微调。
- **配置迁移粒度**：§2.2 的映射是预期值，`TODO(config)` 项以 M3 实现为准。
- **内部版本号**：core bundle 的 `[bundle].version` 与内置插件 `version` 仍为 0.1.0（本 M5 只改发行版本号，
  内置版本随 M2/M3 合流统一）。
- **发行元数据不一致**：`pyproject.toml` 的 `description` 仍写 “Python port of DeepSeek Harness (DSH)”，
  与 README 及本文的 native harness 定位冲突；本 M5 按“只改版本、不动依赖”的约束未改，发布前需集成 owner
  决定是否随去品牌一并更新。
- **测试基线依赖未入库 fixtures**：`fixtures/manifest.json` 由 `tools/gen_fixtures.mjs` 从本机 DSH 数据生成，
  故意不入库；干净 worktree 上 `uv run pytest` 在 `tests/session/test_reader.py:23` 导入期报
  `FileNotFoundError`，其余旧 fixture 测试 fail/skip。发布前需完成 native fixtures 迁移，或让缺失 fixture
  优雅 skip（`TODO(fixtures)`）；这同时阻断“0 skip”门禁。
- **无遥测**：0.2.0 不实现 telemetry/上报；只有本地 trace，且不含 prompt/消息/工具输出正文。
- **trace 不导出 OTLP**：schema 1 §8.6 只定义 OpenTelemetry 字段映射计划，尚无 exporter。
- **Windows 沙箱**：`enforcement=partial`（受限 token/ACL），不是完整 OS 隔离。
- **native 覆盖缺口**：M1 基线未覆盖 image/approval/compaction/MCP/PTC/subagents/multi-agent handoff，随 M2–M4 补测。
- **旧 DSH 引用未清零**：`src` 仍约 379 行 dsh 命中（大小写不敏感），清理建议见 `docs/release/dsh-audit.md`，
  本 M5 不改 `src` 除版本号外的代码。
