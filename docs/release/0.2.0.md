# Release 0.2.0（release candidate）

> **状态：release candidate，未打 tag。** 代码与门禁基线为 `main` 的 `6d57d7a`（2026-11-18），覆盖 M1–M5 的最终交付；其后的文档整理提交不改变代码。
> `main` 已包含 M1 `35b433f`、M2 `0c6be95`、M3 `fff020b`、M4 `1604a34`、M5 `b683b57` 与集成校正。
> **发布定位**：三条主线已交付并通过四道门禁；native loop 仍是 headless 的显式开关，TUI 与默认 headless
> 继续走 v4。0.2.0 是“native 过渡版”，不是 native-only 的最终切换；v4 的完整移除排在 0.3。

## 1. 版本主题

0.2.0 是 DeepPyro Harness 的第一次破坏性版本，主题是三条主线（ADR D5）：

- **插件化（P）**：一种 mount 形状（`setup(self)`）、typed `inject`、服务类型化、能力清单 `CapabilityManifest`。
- **Python 化（Y）**：native schema 1、Python 消息/事件/循环类型，不再复刻外部 harness 的 wire 形状。
- **AI 原生（A）**：session log 只记事实，token/时延/重试进本地 trace；已具备回放、checkpoint、eval、memory
  与 supervisor 的骨架。

一句话：0.2.0 起 DeepPyro 以 native 契约为目标形态；默认运行时尚未完成切换，见 §5。

## 2. 破坏性变更

### 2.1 会话：native schema 1 成为新契约

- native 路径只读写 `~/.dpro/sessions/<session-id>.jsonl`：封闭 header + 27 个核心 `EventKind`（dotted 小写名）。
- native 路径拒绝 `session.v4.jsonl` / `.zstd`（`SessionV4Error`），不降级、不 dual-write、不提供导入。
- 默认 v4 路径仍**暂时**保留并继续读写 `session.v4.jsonl`；两条路径不混用。v4 的 reader/provider/`core.wire`
  未在 0.2.0 删除。
- native 侧删除的 v4 机制：`surfaceOp`、`sourceEventSeqs`、`ignorable`、斜杠记录类型、interval surface folding；
  消息以稳定 `message.id` 定位（替换用 `message.replaced` / `compaction.done` 表达）。
- 影响：依赖 v4 会话形状的脚本/视图/插件在 native 路径上需要重写；v4 会话不能在 native 路径打开。

### 2.2 配置：camelCase → snake_case

- 模型属性、dump、`DEFAULT_TOML` 与文档以 snake_case 为准：`base_url`、`api_key_env`、`context_window`、
  `max_tokens`、`max_steps`、`session_dir` 等。
- 0.2.0 为兼容已有 `~/.dpro/config.toml`，所有配置模型设置 `populate_by_name=True` 并保留 camelCase **alias 读取**；
  写入与新增配置一律 snake_case。alias 的移除是 0.3 的 breaking change。
- 配置模型仍为 `extra="allow"`，未知键不会被拒绝；这是兼容窗口的一部分，0.3 再决定是否收紧。

### 2.3 插件 API：v2 → v3 硬切

- `API_VERSION = 3`，无兼容 shim；v1/v2 插件、带位置参数的 `setup(self, ctx, config)`、`api_version < 3` 的 bundle
  在加载期被 `PluginError`/`CompositionError`/`KernelBootError` 拒绝，并给出迁移提示。
- 唯一 mount 形状：adapter 以 `(ctx, config)` 构造，fiber 激活调用无参 `setup(self)`，插件读 `self.ctx` / `self.config`；
  唯一挂载入口是 `RuntimeContext.mount(plugin, config)`（`PluginContext.mount` 转发）。
- typed 依赖：`inject` 可声明契约类（推荐）或服务名；`PluginContext.get/require/has` 只接受契约类，字符串抛 `TypeError`；
  插件侧字符串 `.service("name")` 与 `__getattr__` 回退已删除。src 中 `.service("` 调用为 0。
- 例外：host 级 `App.service(name)` / `App.get(str)` / `has_service(str)` 作为**弃用的 embedder/test helper** 保留，
  不在插件 API 内，插件够不到。
- 新增 `api/capabilities.py`：`CapabilityManifest` / `ToolCapability` / `TokenCost` / `RiskLevel` /
  `build_manifest` / `tool_capability`；全部 core 插件与 43 个内置工具都有 manifest。`BaseTool.risk`/`idempotent`
  不进入 model-facing schema，工具快照字节不变。
- entry points 与 bundle 目录插件走 v3 loader；`kernel/bundle_schema.py` 校验 `api_version == 3`，bundle 省略该键时默认 3。
- 完整迁移步骤与逐项对照：`docs/plugins/migration-v2-v3.md`；插件作者指南：`docs/plugins/README.md`。

### 2.4 旧 DSH 路径归档 / 去品牌

- `docs/spec/INTERFACES.md`、`docs/spec/session.md` 已冻结并标记由 native 契约取代；
  `dsh-event-catalog*` 两篇是外部 harness 逆向目录，随 v4 移除退役。
- 旧 DSH 路径（`~/.dsh`、DSH 事件名、TS/Node fixtures、`tools/gen_fixtures.mjs`）不再作为产品依赖；CI 不安装 Node。
- 去品牌门禁尚未达标：`src` 仍有约 379 行 `dsh` 命中（大小写不敏感，91 个文件），审计与清理建议见
  `docs/release/dsh-audit.md`。

## 3. 迁移步骤

### 3.1 普通用户

1. 备份 `~/.dpro`（尤其 `sessions/`）。native 与 v4 两种会话互不读取，备份是唯一恢复手段。
2. 需要保留旧会话历史时，用仓库之外的一次性导出脚本转成文本/JSON；0.2.0 不提供导入。
3. 按 §2.2 把 `~/.dpro/config.toml` 改写为 snake_case（旧 camelCase 键在 0.2.0 仍能读，但不要依赖）。
4. 启动 `dpyro` 验证 provider/model/权限配置；默认仍打开 v4 会话。要试用 native，使用
   `dpyro --headless --native-loop ...`，它写新格式会话。
5. 旧 `plugins.toml` / 用户 bundle 按 `docs/plugins/migration-v2-v3.md` 迁移到 API v3。

### 3.2 插件作者

1. 必须直接迁移到 v3：声明 `api_version = 3`，把 `setup(self, ctx, config)` 改为无参 `setup(self)`，
   依赖改用契约类 `inject`/`ctx.get`。v2 插件在 0.2.0 不能运行，没有 shim。
2. 配置字段改 snake_case；去掉对 `core.wire`、`session.v4`、`surfaceOp` 的依赖。
3. 补 `CapabilityManifest`（提供的服务/工具/权限/风险/token 成本）；bundle 的 `api_version` 改为 3。
4. 用 `boot(cfg, bundle_paths=[...])` + `dpyro plugin doctor` 回归；entry point 插件在装载时校验版本。

### 3.3 集成/运维

1. 升级到 `deeppyro-harness==0.2.0`（发布后）；环境变量名不变：`DEEPPYRO_HOME`、`DEEPPYRO_CONFIG`、
   `DEEPPYRO_SESSIONS_DIR`、`DEEPPYRO_TRACES_DIR` 等。
2. 确认 CI 不安装 Node；native 差分/replay 为 `.github/workflows/native.yml` 的非阻塞任务。
3. 0.2.0 没有遥测上报；本地 trace 只含 hash/计数/时延，不能替代业务日志。
4. 回滚：重新安装 `0.1.x` 并使用升级前备份的 `~/.dpro`；native 产生的新会话不能降级读取。

## 5. 已知限制（0.2.0 发布时仍存在）

> 完整逐项清单、状态与证据见 [0.2.0-known-issues.md](0.2.0-known-issues.md)；本节只是发布摘要，冲突以总表为准。

- **native loop 仍是 opt-in**：只有 headless `--native-loop` / `DEEPPYRO_NATIVE_LOOP=1` 走 native schema 1 与
  `AgentLoop`；TUI 和默认 headless 仍走 v4，v4 provider/`core.wire` 未删除。完整切换与删除排在 0.3。
- **两种会话并存**：native 写 `<session-id>.jsonl`，v4 写 `session.v4.jsonl`；互不读取、不 dual-write，
  备份/迁移必须区分。
- **配置兼容窗口**：camelCase alias 仍可读取；移除别名是 0.3 的 breaking change。未知键仍被 `extra="allow"` 接受。
- **memory/eval 未闭环**：SQLite FTS5 long-term memory 未暴露为工具、未自动写入；eval 只有 fixture/scripted
  runner，没有接 native `AgentSession` 的 live runner；supervisor 未接真实 subagent 生命周期（`SubagentResult`
  没有 token/step usage）。
- **UsageService 只是骨架**：`builtin/usage.py` 未挂入 core bundle；纯 host 风格插件仍可经 kernel `ctx.mount`
  挂载，但没有 `CapabilityManifest`。
- **内置版本未统一**：core bundle 的 `[bundle].version` 与内置插件 `version` 仍为 0.1.0；本版本只改发行版本号。
  发行元数据（`pyproject.toml` description、`src/deeppyro/__init__.py` docstring）已改为 native harness 定位。
- **无遥测**：0.2.0 不实现 telemetry/上报；只有本地 trace，且不含 prompt/消息/工具输出正文；不导出 OTLP。
- **Windows 沙箱**：`enforcement=partial`（受限 token/ACL），不是完整 OS 隔离。
- **native 覆盖缺口**：image/approval/compaction/MCP/PTC/subagents/multi-agent handoff 仍未进入 native 差分基线。
- **旧 DSH 引用未清零**：`src` 约 379 行 dsh 命中（大小写不敏感），清理建议见 `docs/release/dsh-audit.md`。
