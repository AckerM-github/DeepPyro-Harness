# Release 0.2.0（release candidate，历史）

> **历史发布说明（0.2.0，已过时）。** 0.3.0 已删除 v4 会话栈、`--legacy-v4`/`--native-loop` 回退开关与
> `dpyro migrate`；本文件中的迁移步骤、v4 路径与 TUI 状态只用于追溯 0.2.0 当时的行为，不再是现行说明。
> 现行发布说明见 [0.3.0.md](0.3.0.md)。

> **状态：release candidate，未打 tag。** 代码基线为 `main` 上的 0.2.0 修复轮提交（2026-11-18）；
> 包含 M1 `35b433f`、M2 `0c6be95`、M3 `fff020b`、M4 `1604a34`、M5 `b683b57`、集成校正与本次
> “已知问题清理”轮（KI-001…KI-037，逐项见 [0.2.0-known-issues.md](0.2.0-known-issues.md)）。
>
> **发布定位**：三条主线已交付并通过四道门禁；**headless 默认走 native**，TUI 交互仍走 v4。
> 0.2.0 是“native 过渡版”，不是 native-only 的最终切换；v4 的完整移除排在 0.3。
> 两种会话格式已有官方迁移命令，但回滚不是逐字节等价。

## 1. 版本主题

0.2.0 是 DeepPyro Harness 的第一次破坏性版本，主题是三条主线（ADR D5）：

- **插件化（P）**：一种 mount 形状（`setup(self)`）、typed `inject`、服务类型化、能力清单 `CapabilityManifest`；
  settings 跨进程锁、行级 manifest 编辑、bundle digest 钉住、TUI slot append-only。
- **Python 化（Y）**：native schema 1、Python 消息/事件/循环类型，headless 默认切换；`core.wire` 只服务 v4
  并有防回潮测试。
- **AI 原生（A）**：session log 只记事实，token/时延/重试进本地 usage 与 trace；已具备回放、checkpoint、
  live eval、memory 工具、Task/Handoff 与 supervisor usage。

一句话：0.2.0 起 DeepPyro 以 native 契约为目标形态，headless 默认已经落在 native 上；TUI 是最后一块
未迁移的交互面，但已能只读列出/查看 native 会话（见 §5）。

## 2. 破坏性变更

### 2.1 会话：native schema 1 成为 headless 默认

- native 路径只读写 `~/.dpro/sessions/<session-id>.jsonl`：封闭 header + 30 个核心 `EventKind`（dotted 小写名），其中 `task.state` / `task.handoff` / `task.handoff.result` 记录 task 插件的任务与 handoff 事实。
- **headless `run_once` 默认 native**；`--legacy-v4`（或 `DEEPPYRO_NATIVE_LOOP=0`）回退 v4，
  `--native-loop` 仍受理但已弃用（`DeprecationWarning`）。TUI 交互仍写 v4，但 `/sessions`、`/resume`
  已能只读发现并渲染 native 会话，不会 attach 或改写它。
- native 路径拒绝 `session.v4.jsonl` / `.zstd`（`SessionV4Error`），不降级、不 dual-write；v4 路径也不读 native。
- 新增 `dpyro migrate`：在两种格式间做一次性转换并默认留 `.bak`；转换会丢弃目标格式无表达的状态
  （native→v4 不保证逐字节等价；v4→native 丢弃图片与 approval/goal/plan/todo 等），边界见
  [guides/session-migration.md](../guides/session-migration.md)。
- native 侧删除的 v4 机制：`surfaceOp`、`sourceEventSeqs`、`ignorable`、斜杠记录类型、interval surface folding；
  消息以稳定 `message.id` 定位（替换用 `message.replaced` / `compaction.done` 表达）。

### 2.2 配置：camelCase → snake_case

- 模型属性、dump、`DEFAULT_TOML` 与文档以 snake_case 为准：`base_url`、`api_key_env`、`context_window`、
  `max_tokens`、`max_steps`、`session_dir` 等。
- 0.2.0 **直接移除** camelCase alias（7 个键：`baseURL`、`apiKeyEnv`、`apiKey`、`maxTokens`、
  `maxSteps`、`contextWindow`、`sessionDir`）；旧键在加载时失败，并在错误里给出 snake_case 替代。
- 配置校验始终严格：schema 表中的未知键抛 `ConfigError`；只有顶层插件表与文档化的适配器选项
  （`max_tokens`、`reasoning_effort`、`input_modalities`）保持开放。`strict_config` / `strictConfig`
  开关本身也被拒绝；`DEEPPYRO_STRICT_CONFIG` 仅保留给 preset model 校验。
- 迁移步骤见 [guides/config-migration.md](../guides/config-migration.md)。

### 2.3 插件 API：v2 → v3 硬切

- `API_VERSION = 3`，无兼容 shim；v1/v2 插件、带位置参数的 `setup(self, ctx, config)`、`api_version < 3` 的 bundle
  在加载期被 `PluginError`/`CompositionError`/`KernelBootError` 拒绝，并给出迁移提示。
- 唯一 mount 形状：adapter 以 `(ctx, config)` 构造，fiber 激活调用无参 `setup(self)`，插件读 `self.ctx` / `self.config`；
  唯一挂载入口是 `RuntimeContext.mount(plugin, config)`（`PluginContext.mount` 转发）。
- typed 依赖：`inject` 可声明契约类（推荐）或服务名；`PluginContext.get/require/has` 只接受契约类，字符串抛 `TypeError`；
  插件侧字符串 `.service("name")` 与 `__getattr__` 回退已删除。src 中 `.service("` 调用为 0。
- host 级 `App` 同样只接受契约类：`App.get(Contract)` / `App.require(Contract)`；过渡期的
  `App.service(name)` / `App.get(str)` / `App.has_service(str)` 已按 KI-035 删除，24 个测试文件 155 处调用点一并迁移；
  新增回归测试禁止字符串 helper 回流。
- 新增 `api/capabilities.py`：`CapabilityManifest` / `ToolCapability` / `TokenCost` / `RiskLevel` /
  `build_manifest` / `tool_capability`；全部 core 插件与 43 个内置工具都有 manifest。`BaseTool.risk`/`idempotent`
  不进入 model-facing schema，工具快照字节不变。kernel 在 boot 前校验重名与版本冲突。
- entry points 与 bundle 目录插件走 v3 loader；`kernel/bundle_schema.py` 校验 `api_version == 3`，bundle 省略该键时默认 3。
- 完整迁移步骤与逐项对照：`docs/plugins/migration-v2-v3.md`；插件作者指南：`docs/plugins/README.md`。

### 2.4 插件平台加固

- settings 写入在跨进程文件锁内做 CAS+merge（Windows `msvcrt` / POSIX `fcntl`，默认 5s 超时），并发写不再丢更新。
- 用户 manifest 改为行级编辑：保留注释、键顺序与未知键；内容无变化时字节不变；坏文档回退全量重写。
- bundle 支持可选 `[bundle].digest = "sha256:…"`：声明后按磁盘字节校验，不匹配 `KernelBootError` 拒绝启动。
- TUI slot 贡献强制 append-only：重复 `(kind, id)` 抛 `SlotError` 并报告双方 plugin id；`dispose` 只删自己的贡献。
- 切换 preset 不再改写已存在会话的 header（`createdAt`/`cwd`/`agentPreset` 等保持），失败会回滚；
  preset `model` 在 add/resolve 时校验，未知模型默认告警、strict 下拒绝。

### 2.5 旧 DSH 路径归档 / 去品牌

- `docs/spec/INTERFACES.md`、`docs/spec/session.md` 已冻结并标记由 native 契约取代；
  `dsh-event-catalog*` 两篇是外部 harness 逆向目录，随 v4 移除退役。
- 旧 DSH 路径（`~/.dsh`、DSH 事件名、TS/Node fixtures、`tools/gen_fixtures.mjs`）不再作为产品依赖；CI 不安装 Node。
- 模型可见文案（沙箱策略描述）已不再出现 “DSH”；`src` 中剩余的 `dsh` 是 v4 事件目录/对照注释，
  共 **377 行 / 94 个文件**，随 v4 删除，见 `docs/release/dsh-audit.md`。

## 3. 迁移步骤

### 3.1 普通用户

1. 备份 `~/.dpro`（尤其 `sessions/`）。
2. 需要保留旧会话时用 `dpyro migrate` 转换，而不是手工拷贝：
   `dpyro migrate --to native --session <id> --dry-run` 先看计划，再去掉 `--dry-run`；
   `--all` 批量转换；默认写 `.bak`，已存在目标需 `--yes`。
3. 按 §2.2 把 `~/.dpro/config.toml` 改写为 snake_case；旧 camelCase 键会直接报错并给出替代名。
4. 启动 `dpyro` 验证 provider/model/权限配置；TUI 仍打开 v4 会话，但会只读列出 native 会话；headless 默认写 native。
5. 旧 `plugins.toml` / 用户 bundle 按 `docs/plugins/migration-v2-v3.md` 迁移到 API v3。

### 3.2 插件作者

1. 必须直接迁移到 v3：声明 `api_version = 3`，把 `setup(self, ctx, config)` 改为无参 `setup(self)`，
   依赖改用契约类 `inject`/`ctx.get`。v2 插件在 0.2.0 不能运行，没有 shim。
2. 配置字段改 snake_case；去掉对 `core.wire`、`session.v4`、`surfaceOp` 的依赖。
3. 补 `CapabilityManifest`（提供的服务/工具/权限/风险/token 成本）；bundle 的 `api_version` 改为 3。
4. 用 `boot(cfg, bundle_paths=[...])` + `dpyro plugin doctor` / `dpyro plugin inspect` 回归；entry point 插件在装载时校验版本。

### 3.3 集成/运维

1. 升级到 `deeppyro-harness==0.2.0`（发布后）；环境变量名不变：`DEEPPYRO_HOME`、`DEEPPYRO_CONFIG`、
   `DEEPPYRO_SESSION_DIR`、`DEEPPYRO_TRACES_DIR`、`DEEPPYRO_USAGE_DIR`。
2. 确认 CI 不安装 Node；native 差分/replay 在 `.github/workflows/native.yml` 中**已是阻塞任务**（KI-031）。
3. usage 写 `~/.dpro/usage/usage.jsonl`，trace 写 `~/.dpro/traces/`，都只含 hash/计数/时延，不含 prompt 与正文；
   配置 `observability.otlp` 后才显式导出 OTLP/HTTP(JSON)，默认关闭。
4. 回滚：重新安装 `0.1.x` 并使用升级前备份的 `~/.dpro`；或先 `dpyro migrate --to v4` 把 native 会话转回
   （仅保证 v4 reader 可读与对话内容）。

## 5. 已知限制（0.2.0 发布时仍存在）

> 完整逐项清单、状态与证据见 [0.2.0-known-issues.md](0.2.0-known-issues.md)；本节只是发布摘要，冲突以总表为准。

- **TUI 交互未迁移（KI-001 partial）**：headless 默认 native，但 TUI 交互仍写 v4；`/sessions` 与 `/resume`
  已能只读列出并渲染 native 会话（KI-037 resolved），但不能在 TUI 中继续对话。v4 provider/`core.wire`
  未删除，完整切换排在 0.3。
- **两种会话并存（KI-002 resolved，边界仍在）**：`dpyro migrate` 可转换并留 `.bak`，但不 dual-write、不互读，
  回滚不是逐字节等价。
- **配置兼容窗口已关闭（KI-013 resolved）**：camelCase alias 与 `strict_config` 开关都已移除，加载始终严格；
  迁移见 [guides/config-migration.md](../guides/config-migration.md)。
- **memory 存储仍是 SQLite FTS5（KI-014 resolved 的边界）**：`memory_search`/`memory_add` 已接线且按 preset
  控制写入，但无 embedding/向量检索，也不自动写入。
- **trace 默认本地（KI-012 resolved）**：不含正文；OTLP 需显式配置；native 与 v4 都会写本地 trace（v4 由 `TelemetryPlugin` 从钩子与会话记录派生）。
- **headless usage 摘要**：`cached` 来自本轮 native run 的真实累计值（KI-036 resolved）。
- **Windows 沙箱**：`enforcement=partial`（受限 token/ACL），不是完整 OS 隔离（KI-020 accepted）。
- **native 覆盖（KI-011 resolved）**：合成差分覆盖七类形状（含 handoff），7/7 covered；录制基线仍不含它们
  （KI-034 accepted）。handoff 的 v4 usage 留在会话记录，native 只进 trace（schema §8.5），差分按该边界断言。
- **去品牌未清零（KI-032 accepted）**：`src` 377 行 dsh 命中，随 v4 删除。
