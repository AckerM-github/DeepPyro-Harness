## 1. 图例与维护规则

| 字段 | 取值 | 含义 |
| --- | --- | --- |
| 严重度 | `S1` | 发布定位或数据风险；不解决就必须在 release note 顶部显式声明，不能静默发布 |
|  | `S2` | 功能缺口或用户可见限制；已有 workaround 或明确的后续版本 |
|  | `S3` | 文档、测试、工程债；不阻塞使用，但会降低可维护性 |
| 状态 | `open` | 仍未完成 |
|  | `accepted` | 有意保留的设计/兼容行为，不是 bug；后续版本可重新评估 |
|  | `resolved` | 已由后续提交解决，保留记录防止重复登记 |
|  | `decision` | 需要发布负责人拍板，未拍板前不能关闭 |

维护规则：

1. **ID 不复用。** 关闭的条目保留原 ID 和 `resolved` 状态；新问题追加新 ID。
2. **一行一件事。** 不要把多个独立缺口塞进同一行；确实同源的用同一行的分号列出。
3. **证据必须可点。** 优先链到代码/文档的具体行；行号会随文档修改漂移，改文档时顺手更新。
4. **摘要不复制整表。** README/release note 只列 S1 和发布必须知道的 3–5 条，其余指回本文。
5. **发布前复核。** 打 tag 前逐行确认 S1 全部有结论、`open` 的 S2 在 release note 可见。

## 2. 发布判断（2026-11-18）

- 按当前定位可以发布 **0.2.0 release candidate**：四道门禁绿，native 路径可用，v4 路径保留可回退。
- **不能**把 0.2.0 宣称为 native-only 或“v4 已移除”：native loop 仍是 opt-in，TUI/`run_code`/默认 headless
  仍走 v4（KI-001），且两种会话格式互不读取（KI-002）。
- 若要直接发 **0.2.0 final（非 rc）**，必须先对 KI-001、KI-002 给出明确结论：接受“过渡版”定位，或推迟
  final 到默认切换之后。当前 release note 已按 rc 写，未打 tag。

## 8. 0.3 候选范围（不是承诺）

按依赖顺序排列；每项进入 0.3 前必须先更新 ADR 与本文：

1. **默认切换**：native loop 成为 headless/TUI 默认，`--native-loop` 改为回退开关（KI-001）。
2. **v4 退出**：provider port、删除 `core.wire`/`llm/` v4、清理 38 个 importer 与 `native_provider` seam（KI-010、KI-032）。
3. **会话迁移**：`dpyro migrate` 或导出/备份工具，明确回滚边界（KI-002）。
4. **配置收口**：移除 camelCase alias、收紧 `extra`（KI-013）。
5. **native 覆盖**：image/approval/compaction/MCP/PTC/subagent 差分（KI-011、KI-034）。
6. **memory/eval 闭环**：long-term tool/自动捕获、live eval runner、supervisor usage（KI-014–KI-016）。
7. **测试门禁**：native CI required、clean checkout 不再 skip reader（KI-030、KI-031）。
8. **文档/品牌**：删除 legacy specs、去品牌（KI-032）；文档整理已完成（KI-033 resolved）。
